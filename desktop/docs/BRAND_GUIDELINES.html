Foundation

Calm by design.
Safe by behavior.

Tidy helps macOS power users understand reclaimable space and approve maintenance without surrendering control.

The brand promise is “See clearly. Tidy safely.” This is a behavioral standard, not marketing decoration: preview precedes execution, refusals name their cause, and destructive actions remain reversible where supported.

Public product surfaces use Tidy. Rust crate names, IPC compatibility events, shared operation logs, and references to the Mole CLI keep their existing names. This preserves interoperability while giving the desktop app a distinct identity.

Shared state remains under ~/.config/mole; operation and deletion history remain under ~/Library/Logs/mole. The native bundle and LaunchAgent use com.tw93.tidy and migrate the exact legacy placeholder identifier.
Logo

The Flow mark

A capital T formed by a graphite crossbar and turquoise folded stem. The curved seam represents a candidate moving from inspection into an intentional action.

Tidy

Use the complete white tile as one indivisible mark. Its restraint is part of the identity: one fold, one direction, one decision.

Voice

Write calm, literal interface copy. Name the action the user controls: “Review 12 items”, “Move to Trash”, or “Try scan again”. Confirmation and completion use the same verb. Errors state the cause and the next available action; avoid vague messages and promotional language.

Layout

Dense enough to inspect.
Open enough to decide.

The interface uses a 4 px base unit, restrained radii, and one clear hierarchy per screen: title, current measurement or task, primary action, then detail.

Default content width is 980 px with 28 px window gutters. Dense rows are 44–52 px high; controls are at least 32 px. Use 8 px radii for compact controls, 12 px for panels, and 18 px for sheets. Reserve pills for navigation, filters, and statuses.

Components

Stable landmarks.
Literal actions.

Components make state visible. Decoration never competes with candidate evidence, confirmation, or refusal causes.

Navigation

The centered graphite pill is the stable app landmark. Show the 34 px Tidy tile first, followed by short nouns. The active destination uses white fill and graphite text; navigation never changes position between routes.

Buttons and controls

  • Use one primary action per region: white fill on dark, graphite text.
  • Secondary actions use transparent or raised graphite with a visible border.
  • Use red only for the final confirmed destructive action.
  • Keyboard focus uses a 2 px bright-teal ring with a 2 px offset.
  • Disabled controls retain their label and expose the reason nearby.

Panels, lists, and data

Panels separate meaning, not decoration. Align file sizes and percentages by decimal position. Paths use SF Mono, truncate in the middle when necessary, and reveal their full value on hover or focus. Empty states state what was checked and offer the next useful action.

Safety flow

One plan.
Five visible states.

Every destructive surface follows the same candidate set from discovery through result reporting.

ScanPreviewConfirmExecuteResults

Candidate count and bytes remain stable across preview and confirmation. The final button names the outcome, such as “Move 12 items to Trash”. Results separate completed, refused, and failed items; partial success is never rendered as total success.
